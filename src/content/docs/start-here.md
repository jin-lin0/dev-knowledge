这个站点保存工作和学习中实际遇到的开发知识。用户主动问到一个概念、命令或参数，就说明它值得被记住；经过验证后，默认进入知识库，而不是等待它积累到足以写成长文章。

## 从问题到知识

```text
问到或遇到一个技术知识点
        ↓
核对官方资料、源码、配置或实际行为
        ↓
搜索知识库，避免重复
        ↓
原子知识 → 追加到分类速记页
完整主题 → 更新或创建专题文档
```

知识库不复制聊天原文。它只保存可以复习和迁移的结论、用法、边界与来源。

## 哪些内容会被积累

- 基础概念和简短比较。
- Git 等工具的冷门命令、参数和恢复方式。
- 框架、语言和工具链中容易混淆的默认行为。
- 调试过程中发现的通用机制和诊断方法。
- 足以形成教程、指南、参考或原理解释的完整主题。

即使知识点很短，只要它通用、已验证，并且用户确实问到了，就有积累价值。

以下内容不会进入这个知识库：

- 无法验证的猜测。
- 只对某次任务有意义的日志和业务操作。
- 公司内部代码、域名、接口、客户数据、凭据或生产标识。
- 单独维护的 Jimu/积木知识。

## 两种阅读方式

- **速记知识**适合快速复习命令、参数、定义和易错点。
- **专题文档**适合系统理解机制、完成任务或查阅完整参考。

分类速记页会随着实际问题持续增长。多个知识点形成稳定主题后，再升级成专题文章并相互链接。

## 页面信息

知识页面可以标注：

- **类型**：速记知识、教程、操作指南、参考资料或原理解释。
- **适合读者**：阅读前预期具备的背景。
- **最近核验**：页面内容最近一次重新确认的日期。

## 内容和路由

所有文档位于 `src/content/docs/`。例如：

```text
src/content/docs/knowledge/git/quick-notes.md
                         ↓
/knowledge/git/quick-notes/
```

侧边栏根据目录和 frontmatter 自动生成。文件名应尽量稳定；内容可以随着学习持续补充和重组。
