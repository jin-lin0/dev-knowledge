## 单线程限制的是执行 JavaScript 的时刻

同一个 JavaScript 执行线程在同一时刻只执行一段代码，但多个任务可以同时处于未完成状态。请求发出后，网络传输由运行时和操作系统处理，远端服务独立计算；本地线程不需要一直占着 CPU 等待结果。

**并发**表示多个任务的生命周期重叠、交错推进；**并行**表示不同执行资源在同一时刻实际工作。一个 JS 线程可以并发等待多个请求，但这不意味着它同时运行多段 JS。Node.js 内部、操作系统和远端服务也不只有这一个线程。来源：[Node.js 事件循环与非阻塞 I/O](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick)。

## await 暂停当前函数，不阻塞整个线程

调用请求函数会先执行其中的同步部分。它返回一个尚未完成的 Promise 后，`await` 暂停当前 async 函数，让其他就绪代码有机会执行；结果就绪后再恢复后续代码。

下面以浏览器中的相对路径请求为例；在 Node.js 中调用 fetch 时需提供可解析的完整 URL。

```js
// 先发起三个请求，再等待全部结果。
const requests = [fetch('/api/a'), fetch('/api/b'), fetch('/api/c')];
const responses = await Promise.all(requests);
```

这里启动请求的是三次 `fetch()` 调用；`Promise.all()` 负责组合和等待这些 Promise，不会创建线程。只声明三个 async 函数而不调用，也不会自动开始执行。

若每个请求都主要等待远端约 10 秒，且服务端允许同时处理，三次串行等待约 30 秒；一起发出后，整体等待可以接近最慢的一次请求。实际耗时还受远端并发能力、限流和本地同步工作影响。

## 并发上限由任务池的结构保证

有界异步任务池可以启动固定数量的 async 循环。每条循环领取一个任务，等待它完成后才领取下一个；创建两条循环，就最多同时推进两个由该任务池管理的任务。

如果多个循环共享任务游标，应在同一段同步代码中完成读取和递增，再 `await` 任务。普通 JS 回调不会在这段同步代码中途切入，因此不会重复领取同一个索引。若把读取和更新拆到 `await` 两侧，则需要重新考虑竞态。

本地验证使用定时器模拟等待，四个任务分别等待 80、30、30、15 ms，并发上限为 2：A/B 先开始，B 约 32 ms 结束后开始 C，C 约 63 ms 结束后开始 D，最终约 80 ms 完成，峰值活动任务数为 2，且每个任务只执行一次。此验证说明等待可以重叠，并不是实际网络或模型吞吐测试。

## CPU 计算与共享状态仍需另行处理

把耗时的同步循环放进 async 函数，或在其调用前加 `await`，不会把计算移到另一个线程；这段同步计算结束前，其他 JS 任务仍会被阻塞。CPU 密集工作需要考虑拆分执行、Worker 或子进程。来源：[Node.js Worker threads 的适用范围](https://nodejs.org/api/worker_threads.html)。

异步并发任务还会共享当前执行环境中的对象。是否为每个任务复制输入、隔离会话和处理过期响应，属于应用自身的状态管理；并发调度不自动提供这种隔离。进程、线程和 IPC 的区别见[工程工具与系统速记](/knowledge/tooling/quick-notes/#ipc进程间通信)。
